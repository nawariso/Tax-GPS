# TGPS-C03 — ประมาณการภาษีทั้งปีและยอดชำระเพิ่มหรือคืน

Version `0.1` · 25 พฤศจิกายน 2569 (Asia/Bangkok)

Status **IMPLEMENTED** · User acceptance **OPEN** · [ผลตรวจ implementation](../implementation-reports/TGPS-C03-progress.md#2026-11-26--implementation-verification-and-review)

ขอบเขต MVP อ้าง [DEC-033](../DECISIONS.md#dec-033--first-tax-estimate-mvp-coverage-and-c03-requirement-review) · ผลรีวิว [DEC-034](../DECISIONS.md#dec-034--c03-requirement-agreement-and-plan-review) · ที่มา [Product Review R04–R06](../reviews/2026-10-15-product-domain-review.md)

## เป้าหมาย

ให้พนักงานเงินเดือนเห็นว่า จากรายได้ที่รับจริงและรายได้ที่คาดว่าจะได้รับในปี 2569 ภาษีทั้งปีประมาณเท่าไร และถ้าถูกหักภาษีตามประมาณการ จะเหลือชำระเพิ่มหรือคาดว่าจะได้รับคืนเท่าไร ผู้ใช้ต้องย้อนดูที่มาของตัวเลขทั้งสองชุดและแก้ประมาณการได้โดยยอดจริงคงเดิม

## ขอบเขต MVP

- ใช้ปีภาษี 2569 และเงินได้จากการจ้างแรงงานมาตรา 40(1) ตาม coverage ปัจจุบัน ช่อง **เงินเดือนและค่าจ้างอื่นที่รองรับ** รวมเงินได้จากการจ้างงานที่อยู่ใน coverage เดิม เช่น ค่าล่วงเวลา แยกโบนัสออกมาอีกช่องในแต่ละช่วง และรวมแต่ละองค์ประกอบเข้าฐานครั้งเดียว
- ใช้สิทธิที่มีอยู่ตาม contract ปัจจุบันของ C01/C02 แสดงผลได้สำหรับเส้นทางเดิมที่ยืนยันว่าไม่มี PVD และ RMF, [PVD ปกติตาม C02A](TGPS-C02A-pvd-first-slice.md) หรือ [RMF ซื้อเองครั้งแรกตาม C02B](TGPS-C02B-rmf-first-slice.md) เมื่อ facts ที่เกี่ยวข้องครบ
- โปรไฟล์ PVD ร่วม RMF, สิทธิ Thai ESG/ESGX ที่จ่ายแล้ว และสิทธิหรือประวัติอื่นที่อยู่นอก coverage ให้ domain จัดการตามเดิม ระบุรายการที่อยู่นอกขอบเขตและปิดผลตาม readiness เดิม เงินได้นอกขอบเขตทั้งยอดจริงและที่คาดไว้ต้องแจ้งให้ domain ประเมิน
- เงินภาษีที่ใช้เทียบยอดเพิ่มหรือคืนมีเฉพาะภาษีเงินได้หัก ณ ที่จ่ายจากเงินได้ที่รองรับของปีเดียวกัน เครดิตอื่น ภาษีที่ยื่นชำระไว้ แบบยื่นเพิ่มเติม และการส่งแบบภาษีอยู่นอกขอบเขต C03

## รูปแบบการกรอกยอดจริงและยอดคาด

ใช้ยอดรวมสองช่วงเพื่อให้ใช้ยอดสะสมจากสลิปและหนังสือรับรองได้โดยตรง แบบกรอกทีละเดือนช่วยกระทบยอดรายงวดแต่เพิ่มภาระกรอก ส่วนช่องเงินเดือนทั้งปีช่องเดียวมีอยู่แล้วและแยกผลของการแก้ประมาณการออกจากยอดจริงไม่ได้

| ช่วง | ข้อมูลที่แยกเก็บ |
| --- | --- |
| ยอดจริงตั้งแต่ต้นปีถึงวันที่ตัดข้อมูล รวมวันตัดข้อมูล | เงินเดือนและค่าจ้างอื่นขั้นต้นที่ได้รับแล้ว, โบนัสที่ได้รับแล้ว, ภาษีเงินได้ที่นายจ้างหักไปแล้ว |
| ประมาณการหลังวันตัดข้อมูลถึงสิ้นปี | เงินเดือนและค่าจ้างอื่นขั้นต้นที่คาดว่าจะได้รับ, โบนัสที่คาดว่าจะได้รับ, ภาษีเงินได้ที่คาดว่าจะถูกหักเพิ่ม |

- ผู้ใช้ระบุวันที่ตัดข้อมูลภายในปีภาษีด้วยตนเอง ณ 31 ธันวาคม ให้ยืนยันยอดรายได้จริงครบปี และยืนยันศูนย์สำหรับยอดรายได้ช่วงที่เหลือ ยอดภาษีหัก ณ ที่จ่ายที่ว่างใช้กฎข้อมูลขาดตามด้านล่าง และระบุยอดหักช่วงที่เหลือเป็นศูนย์ที่ยืนยันเพื่อคำนวณยอดเพิ่มหรือคืน ข้อมูลจากยอดสะสมหรือหนังสือรับรองที่ครอบคลุมช่วงเดียวกันเป็นหลักฐานของยอดเดียวกัน ใช้กรอกยอดรวมครั้งเดียว
- ยอดเป็น `Money`/`Decimal` ไม่ติดลบ แยกช่องว่างออกจากศูนย์ที่ผู้ใช้ยืนยัน โบนัสที่รับมาแล้วหรือรวมในยอดสะสมต้องอยู่ช่องโบนัสจริงเพียงครั้งเดียว ยอดเงินเดือนกรอกก่อนหัก PVD ภาษีหัก ณ ที่จ่าย และสิทธิลดหย่อน
- ให้ตอบแยกสองช่วงว่ามีเงินได้นอกขอบเขตหรือไม่ โดยเลือก มี / ไม่มี / ยังไม่ทราบ Domain ให้ precedence เดิมเมื่อระบุว่ามี หากช่วงใดยังไม่ทราบและไม่มีสถานะอื่นที่มีลำดับสูงกว่า ให้ `REQUIRES_INPUT` และปิด PIT ของทั้งปี
- ใช้ยอดจ่ายสิทธิที่เกิดขึ้นจริงและ facts สิทธิที่ยืนยันแล้ว ณ วันตัดข้อมูลเป็นสมมติฐานของประมาณการ รวมถึงเงินสมทบประกันสังคมที่จ่ายจริง ให้แสดงชัดว่าประมาณการใช้สิทธิเท่าที่ระบุ ณ วันนั้น การจ่ายเพิ่มหลังวันตัดข้อมูลจะเข้าแบบประเมินเมื่อบันทึกเป็นยอดจริงในรอบถัดไป
- PVD ใช้ยอดสะสมลูกจ้างและฐานค่าจ้างของช่วงที่จ่ายจริงตาม C02A ฐานค่าจ้าง PVD ต้องอยู่ในยอดเงินได้จ้างแรงงานจริงถึงวันตัดข้อมูล หากฐานค่าจ้างสูงกว่ายอดจริงให้ระบุข้อมูลขัดแย้ง แม้ยอดจะต่ำกว่าประมาณการทั้งปี สำหรับเงื่อนไขที่ครอบคลุมทั้งปี เช่น นายจ้างเดียว ให้ผู้ใช้ยืนยันสมมติฐานช่วงที่เหลืออย่างชัดเจนและแสดงกำกับผล ถ้ายังไม่ทราบให้ขอข้อมูลเพิ่มตาม C02A
- RMF ใช้ยอดซื้อจริงสะสมและวันที่ประเมินเดียวกับวันตัดข้อมูลตาม C02B คงรายละเอียดเงื่อนไขและสถานะส่งข้อมูลของ บลจ. ผลที่อาศัย RMF ต้องแสดงว่าเป็นประมาณการภายใต้เงื่อนไขต่อเนื่อง
- เมื่อตัดข้อมูลวันใหม่ ต้องยืนยันยอดจริง ยอดที่เหลือ และข้อเท็จจริงที่ผูกกับวันอีกครั้ง ฟอร์มอาจเก็บค่าเดิมไว้ให้ตรวจ ยอดเดิมกลับมาใช้คำนวณได้หลังผู้ใช้ยืนยันเท่านั้น
- ค่าไม่ถูกต้อง เช่น ยอดติดลบ วันที่ผิดปี หรือยอดช่วงที่เหลือมากกว่าศูนย์ ณ 31 ธันวาคม เป็นข้อผิดพลาดของข้อมูล ปิดผลของคำขอนั้นและระบุชื่อช่อง ค่าไม่ถูกต้องและช่องว่างใช้การจัดการคนละกรณี

## การคำนวณและสถานะผล

1. **รายได้จากการจ้างงานทั้งปี** คือเงินเดือนและโบนัสจริงรวมกับเงินเดือนและโบนัสที่คาดในช่วงที่เหลือ domain ส่งยอดนี้เข้าฐานภาษีที่มีอยู่พร้อม facts สิทธิที่ยืนยัน สูตรภาษี ลำดับคำนวณ และกฎการเผยผลอ้างจาก domain และ pack ที่เลือก
2. **ภาษีทั้งปีโดยประมาณ** คือ PIT ที่ domain คืนเมื่อ baseline `READY` สถานะ `ADVANCED_TAX_PATH_REQUIRED`, `UNSUPPORTED` และ `REQUIRES_INPUT` จาก baseline ใช้ลำดับเดิมและปิด PIT, taxable, ยอดเพิ่มหรือคืน และ export ของ C03
3. **ภาษีหัก ณ ที่จ่ายทั้งปีโดยประมาณ** คือยอดที่หักจริงรวมกับยอดที่คาดว่าจะถูกหักเพิ่มในช่วงที่เหลือ ผู้ใช้ระบุประมาณการเอง เมื่อยอดใดยังไม่ทราบ ให้แสดงเฉพาะยอดองค์ประกอบที่ทราบและระบุชื่อยอดที่ขาด
4. เมื่อ baseline `READY` และยอดหัก ณ ที่จ่ายทั้งสองส่วนครบ ให้คำนวณส่วนต่าง `PIT − ภาษีหัก ณ ที่จ่ายทั้งปีโดยประมาณ` ค่าบวกแสดงยอดคาดว่าชำระเพิ่ม ค่าลบแสดงค่าสัมบูรณ์เป็นยอดคาดว่าจะได้รับคืน ศูนย์แสดงว่าไม่มียอดเพิ่มหรือคืน
5. เมื่อ baseline `READY` แต่ยอดหัก ณ ที่จ่ายส่วนใดขาด ให้ยังแสดงภาษีทั้งปี พร้อมสถานะข้อมูลยอดเพิ่มหรือคืนว่า `REQUIRES_INPUT` และระบุชื่อช่องที่ขาด ผลเต็มปีของยอดหักและส่วนต่างยังว่าง ยอดที่ผู้ใช้ยืนยันเป็นศูนย์จึงเข้าคำนวณได้

## การแสดงผลและตรวจย้อนหลัง

- เสนอหน้าผลภาษาไทยที่เห็นสามบรรทัดก่อนเปิดรายละเอียด ได้แก่ **ภาษีทั้งปีโดยประมาณ**, **ภาษีหัก ณ ที่จ่ายทั้งปีโดยประมาณ** และ **คาดว่าชำระเพิ่ม / คาดว่าจะได้รับคืน / ยังประมาณยอดนี้ไม่ได้** พร้อมวันที่ตัดข้อมูลและที่มาของยอดจริงกับประมาณการ
- คำนวณสถานะและยอดใน domain หน้าเว็บแสดงตามสถานะล่าสุด เมื่อแก้ฟอร์มหรือสลับเส้นทาง ให้ผลและ export เก่าหมดอายุทันที การตอบกลับเก่าใช้แทนข้อมูลล่าสุดไม่ได้
- กรณี baseline `READY` สามารถ export ข้อมูลประมาณการพร้อมวันที่ตัดข้อมูล ยอดจริง ยอดที่คาด facts/เงื่อนไข สถานะของทั้งสองผล และ provenance ของ engine/pack ได้ ถ้ายอดเพิ่มหรือคืนยังขาด ให้ฟิลด์ยอดนั้นเป็น `null` พร้อมเหตุผล Snapshot ต้องผูกกับ facts และเวอร์ชันที่ใช้จริงเพื่อ replay ตรวจผลได้
- เส้นทางระบุรายได้ทั้งปีของเดโมเดิมยังใช้งานได้ตาม contract เดิม เส้นทาง C03 เปิดเฉพาะผลประมาณการภาษีและยอดเพิ่มหรือคืน การทดลองใช้เงินใหม่และการเปรียบเทียบเป็นงาน C04/C05 ตัวคำนวณเป็น deterministic ใช้ standard library และเดโมทำงานบน loopback โดยไม่มีการบันทึกโปรไฟล์หรือ log ยอดที่กรอก

## หลักฐานประกอบและแผนสำหรับรีวิว

- ใช้ [แบบ ภ.ง.ด.91 ปี 2568 ของกรมสรรพากร](https://www.rd.go.th/fileadmin/tax_pdf/pit/2568/241268PIT91.pdf) หน้า 2 ส่วน ก ลำดับ 12 และ 15–16 เป็นตัวอย่างการแยกภาษีที่คำนวณได้ ภาษีที่หักไว้ และยอดชำระเพิ่มหรือเกิน [ต้นฉบับและ SHA-256](../policy-evidence/2026-10-21/pvd-follow-up/manifest.json) เป็นหลักฐานจากแบบปีก่อน ใช้สำหรับโครงผลลัพธ์ของร่าง
- ณ วันที่ตรวจ [หน้ารวมแบบภาษีปี 2569](https://www.rd.go.th/68191.html) ยังไม่แสดงแบบ ภ.ง.ด.91 ประจำปี 2569 ในรายการนั้น ข้อกำหนดการปัดเศษหรือขั้นตอนยื่นแบบปี 2569 จึงอยู่นอกการรับรองของร่างนี้
- ผู้ใช้ยืนยันรูปแบบกรอกยอดรวมสองช่วงและใช้ยอดสิทธิที่จ่ายจริงถึงวันตัดข้อมูล รวมถึงการแสดง PIT เมื่อ baseline พร้อมและเว้นยอดเพิ่มหรือคืนเมื่อข้อมูลหักยังขาด ตาม DEC-034 รายละเอียดทางเทคนิคอยู่ใน [แผนสำหรับรีวิว](../superpowers/plans/2026-11-25-c03-annual-tax-estimate.md) พร้อม [ตัวอย่างตรวจตาม AC01–09](../implementation-reports/TGPS-C03-acceptance-reference.md)
