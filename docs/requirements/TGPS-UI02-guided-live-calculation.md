## เป้าหมายที่ผู้ใช้ขอ

ลดความรู้สึกว่าต้องกรอกข้อมูลจำนวนมาก ทำให้ทราบว่าช่องจำเป็นต้องใส่อะไร
ปรับหน้าตาให้น่าสนใจและมี motion และคำนวณใหม่อัตโนมัติเมื่อเปลี่ยนตัวเลข
โดยไม่ทำให้พื้นที่ผลลัพธ์หายและหน้ากระโดด ผู้ใช้เลือกให้ทำด้วย Codex ในแชตนี้

## แบบที่เสนอให้รีวิว

ใช้ HTML/CSS/JavaScript และ Python server เดิม สีครีม เขียวเข้ม และทองอ่อน
ลดพื้นที่ hero ให้เห็นเครื่องมือเร็วขึ้น ใช้ตัวอักษรอ่านง่าย การ์ดมุมมน เงาเบา
desktop แบ่งพื้นที่ข้อมูลและภาพรวม ผลลัพธ์มีพื้นที่คงที่ระหว่างอัปเดต
mobile เรียงข้อมูลก่อนผลลัพธ์ มีลิงก์ข้ามไปผลลัพธ์และสถานะคำนวณใกล้ฟอร์ม
รักษาการเลื่อนตารางภายใน ไม่ให้ทั้งหน้าเลื่อนแนวนอน

### ฟอร์มแบบเปิดทีละเรื่อง

1. **รายได้และฐานภาษี** เปิดเริ่มต้น: เงินเดือนทั้งปี ประกันสังคมที่จ่ายจริง
   วันที่วางแผน และข้อมูลที่ต้องยืนยันเพื่อให้ฐานภาษีพร้อม ได้แก่สิทธิส่วนตัว
   รายได้อื่น เงินออมเกษียณ และยอด Thai ESG/ESGX เดิม แสดงรายการเหล่านี้ให้เห็น
   ไม่ซ่อนในหมวดเพิ่มเติม พร้อมตัวอย่างการกรอกและข้อความอธิบายผลของค่าว่าง
2. **สิทธิที่มีอยู่** พับได้: บิดามารดา บุตร และดอกเบี้ยบ้าน มีคำอธิบายก่อนเพิ่มรายการ
   แสดงจำนวนรายการและสถานะในหัวข้อ การพับไม่ลบค่าหรือถือว่าผู้ใช้ไม่มีสิทธิ
3. **เงินที่อยากนำมาลอง** พับได้: สินทรัพย์ที่เปลี่ยนเป็นเงินใช้ได้ ค่าใช้จ่ายจำเป็น
   งบทดลอง หนี้ ภาระจ่าย และความคุ้มครอง อธิบายว่าข้อมูลนี้ใช้ตรวจสภาพคล่อง
   และทางเลือก ช่อง unknown ยังคงส่งเป็น unknown

คงช่องเดิมทั้งหมดและเก็บข้อมูลในหน่วยความจำของหน้าเท่านั้น ป้ายกำกับแยก
“จำเป็นต่อฐานภาษี”, “ใช้ตรวจสภาพคล่อง”, “กรอกเมื่อมีรายการ” โดยไม่อ้างว่ากรอกเพียง
เงินเดือนแล้วเพียงพอเสมอ ตัวอย่าง scenario แสดงชัดว่าเป็นข้อมูลทดลองที่ใส่ไว้ให้
ไม่แปลงค่าว่างเป็น 0 หรือยืนยันสิทธิแทนผู้ใช้ ไม่เพิ่มช่องหรือขอบเขตภาษีใหม่

### การคำนวณและผลลัพธ์

- input: รอหยุดพิมพ์ 450ms แล้วส่ง API เดิม; select/date และเพิ่ม/ลบ record
  เข้ากระบวนการเดียวกัน ไม่ยิงคำขอซ้ำจาก input/change ของการแก้ครั้งเดียว
- มีปุ่ม “คำนวณตอนนี้” ให้กดได้ และ scenario คำนวณทันทีหลังใส่ค่าครบชุด
- เมื่อข้อมูลเปลี่ยน ยกเลิกสิทธิใช้งานผลเก่าทันที: latest/export/ตัวเลือกเปรียบเทียบ
  ใช้ไม่ได้ เก็บโครงแผงและขนาดพื้นที่เดิมไว้ พร้อม “กำลังอัปเดต” และ placeholder
  แทนตัวเลขเก่า รวมถึงการ์ด ตาราง และข้อมูล audit เก่า ไม่มีการแสดงยอดล้าสมัย
- รับเฉพาะผลของข้อมูลเวอร์ชันล่าสุด response เก่า/error เก่าเปลี่ยนหน้าไม่ได้
- เมื่อ engine คืนผลสำเร็จ จึงแสดงตัวเลขใหม่ โดยเลื่อนตัวเลขแนวตั้งและ fade
  แต่ละการ์ดเหลื่อมกันสั้น ๆ (ประมาณ 40ms รวมไม่เกิน 350ms) ใช้ค่าปลายทางจริง
  ไม่สร้างค่าภาษีระหว่างทาง ไม่เลื่อนจากยอดเดิมที่หมดอายุ
- เมื่อข้อมูลไม่ครบ/ผิด/นอกขอบเขต ให้แสดงชื่อช่องภาษาไทย ลิงก์ไปช่องที่แก้ได้
  และสรุปสิ่งที่ต้องตรวจ ไม่แสดงผลภาษีหรือ export; ไม่แสดง popup reportValidity
  ระหว่างพิมพ์ ปุ่มคำนวณทันทีจึงตรวจและ focus ช่องที่ขาดได้
- ความหมาย readiness ให้ domain ตัดสินตามเดิม รวมถึงกรณีภาษีพร้อมแต่ข้อมูล
  สภาพคล่องยังไม่ครบ ห้ามเปลี่ยนทั้งหมดให้เป็น blocked เพราะช่อง optional ว่าง
- การเลือกมาเปรียบเทียบล้างทุกครั้งที่ข้อมูลเปลี่ยนตามสัญญาเดิม พร้อมบอกสั้น ๆ
  ว่าให้เลือกใหม่หลังอัปเดต ไม่โอน selection จากผล hash เก่าไปผลใหม่

### Motion และ accessibility

ใช้ CSS/local SVG เดิม เพิ่มการเข้าแผงอย่างนุ่มนวลและ feedback เมื่ออัปเดต
รองรับ prefers-reduced-motion: ปิดการเคลื่อนที่และแสดงค่าจริงทันที
focus มองเห็น label ผูกกับช่อง hint/error ใช้ aria-describedby
สถานะคำนวณใช้ polite live region ไม่อ่านซ้ำทุกหลักของตัวเลข
ไม่มี motion วนต่อเนื่องรบกวน ไม่มี CDN ฟอนต์ภายนอก หรือ dependency ใหม่

## ขอบเขตและข้อเลือกของผู้ออกแบบ

ตัวเลข เวลา motion การจัดกลุ่ม และ debounce เป็นข้อเสนอของ Codex ที่ผู้ใช้ยังไม่อนุมัติ
แก้ presentation JS/HTML/CSS และ frontend lifecycle tests; ไม่แตะสูตร tax core,
policy/catalog, supported coverage, eligibility หรือ readiness และไม่เพิ่ม storage
กฎไม่แสดงผลที่หมดอายุยังคงเดิม จึงใช้โครงผลลัพธ์คงที่กับ motion ของค่าปลายทาง
แทนการคงตัวเลขเก่าไว้ขณะกำลังตรวจข้อมูลใหม่
ไม่แก้ทับงาน CSS/เอกสารที่ยังไม่ commit; ใช้ diff ปัจจุบันเป็นฐาน
ไม่เปลี่ยน C01/C02–C06 หรือถือว่าผู้ใช้รับงาน UI01 แล้ว ไม่มี commit/push/merge ในงานนี้
