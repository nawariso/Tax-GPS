# C02 — สรุปสำหรับรีวิว requirement

วันที่: 2026-10-21 · สถานะ: REQUIREMENT_REVIEW / implementation NOT_STARTED

เอกสารนี้ย่อ [requirement v0.1-draft](TGPS-C02-existing-rights.md) เพื่อให้ตัดสินใจ
ขอบเขตได้ง่าย ไม่เปลี่ยน requirement หรือยืนยันกฎหมาย และยังไม่มี implementation plan

## ขอบเขตที่เสนอให้อนุมัติ

เริ่มสิทธิจากเงินที่จ่ายแล้วตามลำดับ PVD เฉพาะเงินสะสมลูกจ้าง → RMF → Thai ESG
สำหรับผู้มีเงินเดือน 40(1) ปีภาษี 2569 ทำทีละประเภทพร้อมหลักฐานและ fixtures อิสระ
แต่ละประเภทต้องแสดงยอดจ่าย ยอดเข้าเกณฑ์ ยอดใช้สิทธิ และยอดเกินเพดานตรวจย้อนกลับได้

ใช้สิทธิเดิมใน baseline ครั้งเดียว แล้วใช้ผลเดียวกันคำนวณวงเงินคงเหลือและผลของ
เงินใหม่ ไม่หักยอดจ่ายเก่าซ้ำจากงบทดลอง ไม่เลือกสิทธิหรือลำดับเพื่อให้ภาษีดีที่สุดแทนผู้ใช้

## สิ่งที่คงเดิม

- ไม่ทราบไม่เท่าศูนย์; ข้อมูลที่กระทบฐานภาษีไม่ครบหรือรายการยังไม่รองรับต้องปิดผล
- Domain ตัดสิน readiness; UI/export/discovery/candidates ใช้ผลเดียวกัน
- ไม่เพิ่มคำแนะนำผลิตภัณฑ์ การจัดอันดับ การคาดการณ์ผลตอบแทน หรือ storage
- สิทธิใหม่ประเภทประกัน/ครอบครัว และการรับเงินออกหรือแก้ภาษีย้อนหลังต้องมีงานแยก
- ไม่อ้างว่า Thai ESGX/LTF transfer รองรับเพราะมีช่องวงเงินร่วม

## งานที่ทำได้หลังอนุมัติรายละเอียด

1. จัด evidence matrix ต่อ rule: แหล่ง primary, หน้า/มาตรา/ข้อ, ช่วงมีผล,
   applicability ปี 2569, ข้อความรองรับ และวันที่/hash ตามที่ดึงได้
2. ตรวจประเด็น PVD exemption/expense ordering, เพดานและวงเงินร่วม,
   RMF eligibility และ Thai ESG/ESGX interactions ตาม requirement §4–6
3. จัดตัวอย่างคำนวณอิสระผูก C02-AC01–12; จุดที่ยืนยันไม่ได้ยัง fail closed
4. เมื่อ evidence gate ผ่านจึงเขียน plan, DEC สำหรับ treatment/readiness ที่เปลี่ยน,
   version migration และ RED→GREEN ก่อน full verification/review

การอนุมัติที่ขอคือขอบเขตและสัญญาพฤติกรรมใน v0.1-draft ไม่ใช่การรับรองกฎหมาย
หรือการอนุญาตให้ข้าม evidence gate. C01/F09 และ UI visual acceptance แยกกัน
